# 任务分析：行情滞后导致的信号失效排查

> 数据：`signal_records.csv`（原始 1190 行，57 行全列精确重复，去重后 1133 行，record_id 唯一）。
> 铁律：本 README 所有数字均可由 `python signal_analysis.py` 的输出（`outputs/analysis_report.txt`）复算得出。

## 我的判断

### 看到了什么
- 研究员反馈：触发买卖提示后遭遇严重执行滑点与信号误判 → 本任务目标是找出可拦截的行情异常模式。
- 数据里 `signal_time` 带 `+08:00`、`quote_synced_at` 带 `Z`（UTC）：**两列时区不同，直接相减会把 8 小时时差算进去**，这是本数据的第一大坑。
- 57 行全列精确重复（record_id 重复），不去重会虚增样本。
- is_valid 缺失 58 行（4.9%，回传缺失）。

### 根问题
**行情快照滞后（陈旧行情）是信号失效的主因。**

统一时区后计算行情滞后 `quote_lag_min = signal_time - quote_synced_at`（分钟），以 10 分钟为界：

| 行情滞后 | 样本数 | 失效数 | 失效率 |
|---|---|---|---|
| ≤ 10 分钟 | 853 | 45 | 5.3% |
| > 10 分钟 | 225 | 91 | 40.4% |

- 失效信号中 91/136（66.9%）来自滞后 >10 分钟的行情——而这类信号只占已知结果样本的 20.9%（225/1078）。
- 失效组滞后中位数 24 分钟，有效组仅 5 分钟（组间对比见报告第五节）。
- 10 分钟恰好是分布的自然断点：90 分位是 38 分钟、75 分位 8 分钟，(5,10] 与 (10,20] 之间有效率从 95.0% 跳水到 63.5%（见报告第三节分箱表）。
- 其他维度是次要因素：order_depth≤3 手时失效率 27.4%（157 行），但控制滞后后（lag≤10 且 depth≤3）仍有 22.0%，说明深度低与滞后是两个独立风险源；cluster_node / asset_class 之间失效率差异小（约 10%~15%），不构成根因。

### 关键数字
| 指标 | 数值 | 计算方式 |
|---|---|---|
| 去重后行数 | 1133 | `df.drop_duplicates()` 后行数（57 行全列重复） |
| 已知结果样本 | 1078 | is_valid 非 NaN 的行 |
| 失效信号 | 136 | is_valid == 0 |
| lag≤10 失效率 | 5.3%（45/853） | 统一时区后按 10 分钟分箱 |
| lag>10 失效率 | 40.4%（91/225） | 同上 |
| 失效中滞后>10min 占比 | 66.9%（91/136） | 交叉统计 |
| 拦截 lag>10 净收益 | **+2325 元** | 91×75 − 225×20 |

## 做了什么

1. **数据质量核查**：发现 57 行全列重复（去重安全：同 record_id 各行 quote_synced_at、is_valid 完全一致，程序验证 0 矛盾）、is_valid 缺失 58 行。
2. **时区陷阱修复**：`+08:00` 与 `Z` 混用，用 `pd.to_datetime(..., utc=True)` 统一后再相减。若不修复，滞后会被错算 8 小时，全部结论作废。
3. **计算行情滞后** quote_lag_min，做分箱与失效率交叉。
4. **阈值扫描**：对 1/2/3/5/8/10/12/15/20/30 分钟阈值逐一估算成本收益（口径：失效 75 元/次，拦截 20 元/次），lag>10 净收益最高。
5. **规则对比**：单阈值 lag>10 优于「lag>10 且 depth≤3」组合规则（组合会漏掉 lag>10 中 195 行深度正常的信号，挽回损失减少而拦截成本节省有限）。
6. **次要因素验证**：order_depth≤3 失效率 27.4%，是独立的第二风险源，建议作为后续规则（本次未计入净收益估算）。

## 怎么证明有用

### 结论如何支持决策
**上线「行情滞后 >10 分钟即拦截/警告」规则**：按已知结果样本估算，拦截 225 条滞后信号，其中 91 条本会失效，挽回 91×75=6825 元，拦截成本 225×20=4500 元，**净收益 +2325 元**；同时 225 条被拦信号里 59.6% 确实失效，误拦率可接受。这是阈值扫描中所有候选里的最优解。

## 局限与后续

- 成本估算基于历史失效实现值，被拦截信号的"假设失效"用 is_valid=0 近似，存在选择偏差（真实执行后结果可能不同）。
- is_valid 缺失的 58 行滞后分布与全体接近（中位数 5 分钟），缺失大概率与滞后无关。
- 后续可验证：order_depth≤3 作为第二道规则（单独失效率 27.4%，预计再增净收益，需重新扫描避免与 lag 规则重复计数）。
- 48 小时改进窗口：计划补充 lag 阈值与 depth 组合规则的网格扫描、缺失行占比敏感性分析。
